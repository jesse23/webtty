# ADR 062: server — createServer, a session store and a route table

**SPEC:** [architecture](../specs/architecture.md), [webtty](../specs/webtty.md), [config](../specs/config.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

- `src/server/index.ts` does its work at import time (config, port, wasm lookup, servers, signals, listen), so tests can only run the server as a subprocess. `routes.ts`, `websocket.ts` and `index.ts` therefore never appear in coverage, and paths such as a spawn error in `/execute` are not tested deterministically.
- `routes.ts` (485 lines) is one 400-line `handleRequest` if-chain over ten route groups. The 413/400 body-error mapping is written three times, JSON responses are hand-written about 25 times, and the `/execute` child-process streaming and the `/publish` NDJSON splitter sit inside it.
- State is module-global: `sessionRegistry`, an exported `let lastUsedId` mutated through a setter, and `onLastSessionClosed` in `websocket.ts`. `routes.ts` renames and deletes by mutating the map directly.
- `websocket.ts` mixes close codes, session close and broadcast, the ANSI banner and runner detection, PTY spawn and exit, and the client message protocol; the size clamp is written twice.
- `src/config.ts` (369) mixes schema, defaults, file I/O, binding merge rules and a long validator; adding a key touches five places, two of them outside the file.
- `src/pty/index.ts` takes seven positional arguments, reordered by a wrapper. `isBun` has three definitions.
- `src/utils.test.ts` is a helper module that `bun test` also runs as a test file.

## Decision

### createServer

`src/server/app.ts` exports `createServer({ loadConfig, store, spawnPty, paths, onStop })`, returning `{ httpServer, wss, shutdown }`. `src/server/index.ts` stays the entry (so `dist/server/index.js` and every script that names it are unchanged) and only reads the environment, calls `createServer`, listens and installs the signal handlers. `server-paths.ts` is the one module that knows how deep `src/server` and `dist/server` sit, replacing three separate path calculations; it is tested for both layouts.

`loadConfig` stays a function called per request and per spawn, injected rather than imported, so editing the config file still takes effect on the next tab reload (ADR 009) and tests pass a fixed config.

### SessionStore

`sessions/session-store.ts` is a class that owns the map, `lastUsedId`, `create`, `get`, `rename`, `remove`, `findByPid`, `list`, `size` and an `onEmpty` callback (the old "last session closed" handler). One instance is created in `index.ts` and passed in; every reader of `lastUsedId` switches over in the same commit. `sessions/session.ts` holds a session's PTY lifecycle (spawn on first connect, the scrollback ring, exit handling, close, broadcast), moved out of the WebSocket handler. Its order is kept exactly: on connect, the banner, then the scrollback, then `pty.write('\n')`; a reconnecting client gets the replay before the resize; `output.add` precedes the spawn; on exit, the registry entry is removed, then `output.end`, then `onEmpty` after the flush.

### Routes

- `http/router.ts` is a small ordered table (method, pattern, handler); the first match wins, in the old if-chain's order, so precedence is unchanged. An unsupported method still falls through to 404, and CORS headers are on every response.
- Handlers are grouped by resource in `routes/` (`server-routes`, `config-routes`, `session-routes`, `page-routes`, `asset-routes`, `publish-route`, `execute-route`), with `run-command.ts` taking `spawn` by injection.
- `http/respond.ts` and `http/request-body.ts` hold the JSON, text and CORS helpers and the single 413/400 mapping. `src/ndjson.ts` (next to `runtime.ts` and `version.ts`, the root modules the server and CLI share) holds a `LineSplitter` used by `/publish` and by the CLI's `run` (ADR 063).
- Before any route moves, golden tests pin every route's status, body and headers (CORS on a 404, `X-Sessions-Remaining`).

### WebSocket layer

`ws/close-codes.ts` (the `WS_CLOSE` constants), `ws/ws-upgrade.ts` (the `noServer` upgrade router), `ws/pty-socket.ts`, `ws/events-socket.ts` and `ws/client-message.ts` (pure: `parseClientMessage`, which keeps the `startsWith('{')` check before `JSON.parse`, and `clampSize`, the one copy of the 1..1000 × 1..500 clamp with the 80 × 24 default). The banner is the pure `sessions/session-banner.ts`. The per-chunk path (PTY `onData` → scrollback → `OutputPacer.broadcast`) gains no emitter, spread or allocation.

### Config and runtime

- `src/config.ts` becomes `src/config/` with `index.ts` re-exporting what it exports today, so `../config` imports resolve unchanged: `config-schema.ts` (types, `ClientConfig`, `CLIENT_CONFIG_KEYS`, including the legacy `scrollback` key the server still sends), `config-paths.ts`, `defaults.ts`, `parse-config.ts` (pure, one table-driven test per key), `keyboard-bindings.ts` and `client-view.ts` (`toClientConfig`).
- `src/runtime.ts` replaces the three `isBun` definitions with honestly named predicates, one per existing meaning, so no call site changes behaviour.
- `src/pty` takes one options object (`spawnPty(options)`), keeps its `pty: …` log line, and the node-pty backend takes the module by injection so its mapping is tested.
- `flow.ts` becomes `output-pacer.ts` (a `git mv`; it is already clean), and `flow.ts` stays as a one-line re-export until the client's `replay-window.test.ts`, which imports `DEFAULT_FLOW_LIMITS` as a contract, is repointed after the client and server branches merge; `static.ts` becomes `http/static-files.ts`.
- `src/utils.test.ts` becomes `src/test-support/server-harness.ts`.

## Consequences

- Routes, WebSocket channels and sessions run in-process on port 0 in tests, so they count in coverage and edge cases become deterministic; two or three subprocess tests remain as end-to-end checks.
- A new route is a handler and a line in the table; a new config key is the schema, the default, its parse rule and (if the client needs it) the key list, all in `src/config/`.
- Golden tests written before the move make any change in a response visible.

## As built

Recorded when the documentation was reconciled with the code (2026-10-14).

- `server/app.ts` is 88 lines and `server/index.ts` 50. The largest server file is `output-pacer.ts` (278), moved unchanged.
- `flow.ts` was renamed in `6689ece` and kept as a one-line re-export until the merge; `772fc70` repointed the client's `replay-window.test.ts` at `output-pacer.ts` and deleted the shim.
- The whole-server behaviour tests sit at `src/server/` beside `app.ts`: `routes.test.ts` and `websocket.test.ts` (in-process through `createServer`), the three `routes-*golden.test.ts` files, and `entry.test.ts`, the subprocess check of the entry. Server coverage is 100% of lines and functions.
