# ADR 049: client — Mouse reports, cursor style and paste through libghostty-vt

**SPEC:** [client](../specs/client.md), [config](../specs/config.md)
**Status:** Accepted
**Date:** 2026-10-13

---

## Context

ADR 047 left three ADR 041 step 5 replacements as follow-ups, each a behaviour change that needed its own decision. All three are TypeScript re-implementations of something the pinned official wasm (Ghostty `05dcf887`) already does:

- **Mouse reports.** `input-handler.ts` encodes clicks and motion itself, and `terminal.ts` builds wheel reports with `wheelSgr`. It knows two formats: SGR when mode 1006 is on, otherwise X10 bytes. Measured against Ghostty's encoder (`src/input/mouse_encode.zig`):
  - Alt is never reported, and Cmd/Meta is sent as Alt (+8).
  - The back and forward buttons (`MouseEvent.button` 3 and 4) are sent as codes 3 and 4. Code 3 means a release, and code 4 is the Shift bit on a left press. Ghostty sends 128 and 129, as for X11 buttons 8 and 9.
  - UTF-8 (1005), urxvt (1015) and SGR-pixels (1016) are sent as X10 bytes, and the wheel is always sent as SGR 64/65, even when 1006 is off.
  - X10 mode 9 (presses only, no modifiers) gets releases, motion and modifiers.
  - X10 columns or rows above 95 are sent as `String.fromCharCode(32 + n)`. That character goes over the text WebSocket as UTF-8, so the app gets two bytes, not one.
  - A click in the padding is clamped only from below, so the reported cell can be past the grid. A drag that leaves the container stops reporting, because the listeners are on the container, and the release outside it is lost.
- **Cursor style.** `write()` scans every chunk of output with a regex for DECSCUSR (`scanDecscusr`) and keeps the app's shape apart from the configured one (ADR 013). That is about 10% of write CPU. Ghostty already applies DECSCUSR. Its render state, which the binding reads every frame, reports the shape (`visual_style`) and blink (`blinking`). `GHOSTTY_TERMINAL_OPT_DEFAULT_CURSOR_STYLE` and `…_BLINK` set the defaults that `CSI 0 SP q` and RIS restore. A new default applies at once only while the app has not chosen a shape (Ghostty's `setDefaultCursorStyle`).
- **Paste.** `paste.ts` sends text raw, wrapped in `ESC [200~ … ESC [201~` only when mode 2004 is on and the text has a newline (ADR 037). `ghostty_terminal_paste` brackets every paste while 2004 is on. It replaces unsafe control bytes (NUL, BS, ENQ, EOT, ESC, DEL, and ^C ^\ ^U ^Z ^Q ^S ^W ^V ^R ^O, per xterm) with spaces, and turns `\n` into `\r` when unbracketed, so `\r\n` becomes `\r\r` as in xterm. It refuses text that could run commands unless `allow_unsafe` is set, and it sends kitty paste events (mode 5522) only when a clipboard-read callback is installed.

The user approved moving all three to the official APIs.

## Decision

### Mouse: `ghostty_mouse_encoder_*` and `ghostty_mouse_event_*`

The binding gains a mouse encoder per terminal (`OfficialTerminal.encodeMouse`, `setMouseGeometry`). Every mouse report, including wheel ticks, is encoded by it.

- **Modes.** The tracking mode and format come from the terminal through `ghostty_mouse_encoder_setopt_from_terminal`. That call also clears the encoder's last cell, so the binding makes it only when one of modes 9, 1000, 1002, 1003, 1005, 1006, 1015 or 1016 has changed since the last report. Otherwise motion deduplication would reset on every event.
- **Deduplication.** `TRACK_LAST_CELL` is on: Ghostty reports motion once per cell, which replaces `isNewMouseCell` (ADR 041's fix for drags within one cell). As before, any report sets the last cell, including a press, and the last cell resets on a mode or geometry change.
- **Hover.** Ghostty sends motion with no button as 32 + 3 = 35, the code webtty's fix chose (ADR 041), so `mouseMotionButton` goes. A drag reports the lowest held button (left, then middle, then right), as before.
- **Geometry.** The encoder works in whole pixels, with a whole cell size. webtty's CSS cell is fractional, so positions are given in device-pixel cell units: the cell is `deviceCellPixels` (the size Ghostty reports for XTWINOPS 14/16 t and mode 2048, ADR 042), and a CSS offset from the grid's origin is scaled by that cell over the CSS cell. The cell under the pointer is then exact at any column, and SGR-pixels (1016) coordinates agree with the cell size apps were told. The padding is the distance from the grid to the container's edges, rounded in the same units, so the screen is the container. The position is measured from the grid's origin and then offset by the rounded left and top padding, so rounding never moves a cell boundary.
- **Outside the grid.** A press, a release or motion in the padding is reported at the nearest edge cell, as in Ghostty, instead of at a cell past the grid. Motion outside the container is reported only while a button is held and the mode reports motion (1002/1003), clamped to the edge cell. A release is always reported. Move and release listeners are on the document, so a drag that leaves the terminal keeps reporting, and its release is sent. A release outside the container is sent only for a button pressed in it.
- **Buttons and modifiers.** Browser buttons 0, 1, 2, 3 and 4 are Ghostty's left, middle, right, eight and nine. A reported back or forward press and release is `preventDefault`ed, so the browser does not navigate away from the session. Modifiers are Shift (+4), Alt (+8) and Ctrl (+16). Cmd/Meta is not reported, because Ghostty does not encode Super.
- **Wheel.** `TickPacer` still paces the ticks of ADR 045. Each event's tick is encoded once, as a press of button four (up) or five (down) at the pointer's cell with the event's modifiers, and the pacer repeats that sequence. The tick counts (`wheelTicks`, `mouseScrollSpeed`) are unchanged. `wheelSgr` goes. In X10 mode 9 the encoder sends nothing for the wheel, and nothing is queued.
- **Bytes over a text WebSocket.** The encoder returns bytes, and the client sends text frames, which the server writes to the PTY as UTF-8. A report that is not valid UTF-8 cannot reach the app unchanged, so it is dropped. That covers X10 coordinates above 95 (Ghostty's own limit is 223) and X10 buttons 128/129. Sending them would need binary WebSocket frames and a server that writes bytes, which is a protocol change. That limit is documented here instead. Apps that set 1006 (vim, tmux, htop, less) or 1015 are not affected. UTF-8 (1005) reports are valid UTF-8 and are sent.

### Cursor style: from Ghostty's state

- The renderer takes the shape and blink from `getCursor()` every frame (`style`, `blinking`), and repaints the cursor cell when either changes (ADR 015). The binding already reads both from the render state, and maps a hollow block to a block.
- The configured `cursorStyle` / `cursorBlink` go to `GhosttyTerminalConfig` and are set with `DEFAULT_CURSOR_STYLE` / `DEFAULT_CURSOR_BLINK` when the terminal is created, including by `reset()`. An option change at runtime calls the new `setDefaultCursor`. `scanDecscusr`, `decscusrShape`, `CursorShape` and the app-shape state in `terminal.ts` go.
- ADR 013's behaviour is kept. The config sets the default, DECSCUSR 1–6 overrides it, `CSI 0 SP q` and RIS restore it, and changing the config while an app has chosen a shape does not override that shape.

### Paste: `ghostty_terminal_paste`

- `Terminal.paste(text)` passes a `text/plain` paste (source CLIPBOARD, location STANDARD) to `ghostty_terminal_paste` with a mime reader that writes the text. The encoded bytes come back through `WRITE_PTY` and leave through `onData`, like query replies.
- `allow_unsafe` is always set. ADR 037 decided that unbracketed multi-line text is sent rather than refused, and webtty has no confirmation dialog. No clipboard-read callback is installed, so no kitty paste events (mode 5522) are sent.
- ADR 014 and ADR 037's paste UX stays in `index.ts`. Cmd+V and the context-menu paste go through the `paste` event, Ctrl+V reads the clipboard itself, a configured binding still wins, and an empty `text/plain` (an image) or a failed clipboard read sends `\x16`. `encodePaste` goes, and `paste.ts` keeps only the empty-text check.

## Consequences

Mouse, visible to apps:

- Alt-click and Alt-drag carry +8. Cmd-click no longer does.
- Back/forward clicks report 128/129 in SGR, UTF-8 and urxvt, instead of a fake release and a Shift-left press. They are dropped in X10 format, and the browser no longer navigates back on them while an app tracks the mouse.
- Modes 1005, 1015 and 1016 work. The wheel follows the format (`ESC [M` + `` ` ``/`a` bytes in X10 format), carries modifiers, and mode 9 gets no wheel, releases, motion or modifiers.
- In X10 format, reports past column or row 95 are dropped, where they used to arrive mangled.
- Clicks in the padding report the edge cell. Drags past the edge keep reporting at the edge cell, and their release arrives.
- Motion deduplication is Ghostty's: per cell, reset on a mode or geometry change (resize, zoom, padding).

Cursor style:

- The output scan's CPU is gone. The shape is now whatever Ghostty's state says, so these follow Ghostty:
  - Mode 12 (`CSI ? 12 h/l`, ATT610) turns blinking on and off. Vim's xterm `t_vs`/`t_ve` send it, so a cursor can stop or start blinking where the scan ignored it.
  - The shape is kept per screen: leaving the alternate screen shows the main screen's shape again. Blink is a mode, so it is shared by both screens.
  - DECSTR (`CSI ! p`) restores the default.
  - Ps 7 and above are ignored.

Paste:

- With mode 2004 on, single-line pastes are bracketed too.
- Control bytes in pasted text become spaces in both modes. A pasted ESC, ^C or ^U can no longer act as a key.
- With mode 2004 off, newlines are sent as `\r`, and `\r\n` as `\r\r`.

Overall: about 200 lines of encoders and the regex scan go. Every mouse, cursor-style and paste path is now Ghostty's.

## Considered Options

- **Use the official APIs (chosen).** Ghostty's behaviour, tested upstream, with webtty's wheel pacing and transport on top.
- **Fix the TS encoders.** It would mean adding Alt, buttons 8/9, three more formats, mode 9, clamping and drags outside the container, which re-implements `mouse_encode.zig` and keeps it in step with Ghostty by hand.
- **`ghostty_paste_encode` instead of `ghostty_terminal_paste`.** Same bytes today, with no callback. But the terminal call is the one Ghostty recommends: it reads the modes itself and is where kitty paste events live.
- **Binary frames for X10 above column 95.** Needs a protocol and server change for a format that modern apps do not use. Deferred.
- **Ignore mode 12 and keep blink from DECSCUSR only.** That would need the scan again, or a second, JS-side state that could disagree with Ghostty's. Ghostty itself follows mode 12.
