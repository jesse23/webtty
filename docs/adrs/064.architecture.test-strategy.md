# ADR 064: architecture — Test strategy and coverage targets

**SPEC:** [architecture](../specs/architecture.md)
**Status:** Accepted
**Date:** 2026-10-14 (coverage enforcement and listener snapshots revised after review)

---

## Context

`bun test --coverage` reports 89.6% of lines and 82.5% of functions, but only over the files loaded in-process. The client wiring (`index.ts`), `compose.ts`, the server routes, WebSocket layer and entry, the CLI entry and the node-pty backend are not in the table at all. DOM code is the weak spot: `find-bar.ts` 27% of lines, `edge.ts` 52%, vendored `terminal.ts` 53%, `selection-manager.ts` 61%, `url-regex-provider.ts` 8%. There is no DOM in the test runner; tests stub `globalThis.document` and `window` by hand, each vendor test file repeats the wasm path and compiles the wasm again, and 54 casts reach private members.

## Decision

- **Design for tests.** Globals come in through constructors (ADR 059); entries are thin (ADR 060, 062, 063); pure logic is split from DOM and I/O.
- **Placement.** Tests sit next to their module as `x.test.ts`; vendor tests live in `src/client/vendor/tests/`, mirroring the vendored subfolders, with `fixtures/` beside them. Shared helpers live in `test-support/` folders (`src/test-support/`, `src/client/test-support/`, `src/client/vendor/tests/support/`) and are never named `*.test.ts`.
- **Fakes**: `FakeSocket`, `ManualClock` (timers and animation frames), `FakeTerminal` (the slice of `Terminal` features use), `RecordingTarget` (records `addEventListener` and `removeEventListener` with their options), a fake canvas and a fake event target for the vendored layer, a fake `fetch` and a fake PTY for the server and CLI.
- **DOM: `happy-dom`**, a pinned devDependency (`20.14.5`, exact), used only as an explicit `new Window()` per test whose `document` (and, where needed, `window`) is injected into the code under test. It is never registered globally or preloaded, so the existing tests that stub globals, and the wasm tests, run exactly as before. It is a devDependency only; nothing in `dist/` changes. If a case needs real layout (sizes), the test injects the measurements instead.
- **Server and CLI in-process.** Routes, WebSocket channels and sessions are tested through `createServer()` on port 0 with a temporary `HOME`; commands through injected `CliDeps`. Two or three subprocess tests remain to check the entries. No test reads the user's configuration or uses a fixed port.
- **Vendor.** One cached `loadGhostty()` and one wasm path in `vendor/tests/support/wasm.ts`. New tests use the collaborators' public seams instead of private-member casts; existing casts are rewritten as the state they reach moves.
- **Required tests by kind.** Pure modules: table-driven, all branches. Disposables: `dispose()` removes everything it added, and a second call does nothing. Order-sensitive wiring: an order test (client install order, the per-message pipeline, the on-open sequence, the key dispatcher's equivalence with the old listeners, the server's route precedence).
- **Coverage targets**, enforced at the end of the refactor by `bun run test:coverage`: app, server, CLI, config and pty ≥ 95% lines and ≥ 90% functions; vendored layer ≥ 85% lines and ≥ 80% functions; pure modules 100%. Bun's `coverageThreshold` in `bunfig.toml` is a single global setting and cannot vary by folder, so it holds the common floor (85% lines, 80% functions), and `scripts/check-coverage.ts` reads the lcov report (`--coverage-reporter=lcov`) and checks each layer's target; `test:coverage` runs both.
- **Listener snapshots.** Before the vendored facades are split (ADR 061), a test records every listener `Terminal.open()` adds (target, type, capture, order) and which of them `dispose()` removes. Each split step must leave the snapshot unchanged; only the ADR 065 commit changes it.
- **Cross-branch contracts.** Tests may import across the client/server line; source may not. The close codes are pinned by a contract test that imports both sides; the client config type is checked by `tsc` (it is the server's type, imported with `import type`).
- **Structure** is tested too: `scripts/check-architecture.test.ts` (ADR 059).

## Considered Options

- **Hand-written DOM fakes only.** No dependency, but a fake rich enough for `FindBar`, `Composer`, `Terminal.open` and the selection gestures would be a small DOM of our own to maintain. Kept for the few cases where a fake is simpler (event targets, canvases).
- **happy-dom as a global preload** (upstream ghostty-web's setup). Rejected: it changes what every test sees, including those that stub globals today.
- **A browser runner** (Playwright). Rejected for unit tests: slow, a large dependency, and the logic under test does not need a real browser.

## Consequences

- Coverage measures the whole code base, and the targets are concrete.
- DOM views and features get real tests without changing how the existing suite runs.
- The suite stays fast: one wasm compile per process for the vendor tests, in-process servers instead of subprocesses.

## As built

Recorded when the documentation was reconciled with the code (2026-10-14).

- `bun run test:coverage`: 2,899 tests in 216 files pass. Overall 99.89% of lines and 98.57% of functions (test support included). Per layer, as `scripts/check-coverage.ts` reports them: vendored 100% lines and 98.95% functions; client app 100% and 98.20%; server, CLI, config, pty and the shared `src/*.ts` files 100% and 100%. The 41 modules in `PURE_MODULES` are at 100% of lines. Bun counts executable lines, so these line numbers are higher than a statement count would give.
- The check also fails any `src/` source file that no test loads (`f79a2b8`), except the type-only modules and thin entries in `NOT_LOADED`.
- Subprocess tests that remain, as end-to-end checks of the entries: `server/entry.test.ts`, `cli/index.test.ts` and `version.test.ts` (the `--version` of both entries). The route tests run real shells for the execute routes, in-process.
- No test reaches a private member through an `as unknown as {…}` cast any more.
- `happy-dom` `20.14.5` is the one devDependency added (`f2c4939`).
