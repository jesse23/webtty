# ADR 050: client — Selection words, lines and text from libghostty-vt

**SPEC:** [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

`selection-manager.ts` (887 lines) was still almost all of Coder's ghostty-web code. ADR 041 and later ADRs fixed it in place: wide-character spacers (a1671fa), `copyOnSelect`, and selection rows outside the viewport for overscan (ADR 043). Three parts of it re-implement what a terminal engine knows better:

- **Text.** `getSelection` read each row as cells (`getLine`, `getScrollbackLine`), looked up graphemes, skipped spacer cells, trimmed trailing spaces and put a newline after every row. It had no idea of soft wraps, so a long command line or URL that wrapped was copied with a newline in it.
- **Words.** A double click matched `[\w\-./~@+]` on one row. `\w` is ASCII only, so `café` selected `caf` and a CJK word selected nothing; `?`, `=`, `&` and `#` were boundaries, so a URL with a query was cut at the `?`; and a word that wrapped stopped at the row's edge.
- **Lines.** A triple click took column 0 to the last non-blank cell of one row, so a wrapped line selected only the row clicked.

The pinned official wasm (Ghostty `05dcf887`, ADR 042) exports Ghostty's selection API (`include/ghostty/vt/selection.h`, `terminal.h`, `grid_ref.h`, `point.h`):

- `GhosttySelection`: two `GhosttyGridRef` endpoints (inclusive, in either order) and a `rectangle` flag.
- `ghostty_terminal_grid_ref` resolves a `GhosttyPoint` (`ACTIVE`, `VIEWPORT`, `SCREEN` or `HISTORY` coordinates) to a grid reference, and `ghostty_terminal_point_from_grid_ref` goes back.
- `ghostty_terminal_select_word` (default or custom boundary codepoints), `ghostty_terminal_select_word_between`, `ghostty_terminal_select_line` (custom whitespace, optional semantic-prompt bounds), `ghostty_terminal_select_all` and `ghostty_terminal_select_output` derive a selection from a reference.
- `ghostty_terminal_selection_format_buf` / `_alloc` format a selection (plain, VT or HTML) with `unwrap` (join soft-wrapped rows) and `trim` (drop trailing whitespace). Plain with both set is Ghostty's own copy (`Screen.selectionString`).
- `GHOSTTY_TERMINAL_OPT_SELECTION` / `GHOSTTY_TERMINAL_DATA_SELECTION` install and read a terminal-owned selection, kept on tracked references; the render state reports it per row (`GHOSTTY_RENDER_STATE_ROW_DATA_SELECTION`) and per cell (`…_CELLS_DATA_SELECTED`).
- `ghostty_terminal_selection_adjust`, `_order`, `_ordered`, `_contains` and `_equal` work on snapshots, and `ghostty_tracked_grid_ref_*` keeps a reference valid across scrolling, pruning and reflow.
- `ghostty_selection_gesture_*` is a pointer state machine: press, drag, release, autoscroll tick and deep press, with click counting by time and distance, cell, word, line or command-output behaviour per click count, and word- or line-granular drags.

The manifest (`ghostty_type_json`) describes every struct and enum used here.

## Decision

Ghostty decides what a click selects and what a selection copies. webtty keeps the mouse handling and the selection state.

- **Binding.** `GhosttyTerminal` gains `selectWord(cell)`, `selectLine(cell)` and `selectionText(start, end)`, with cells in screen rows (`ScreenCell`: row 0 is the oldest scrollback row, as Ghostty's `SCREEN` points). They call `ghostty_terminal_grid_ref` with `SCREEN` points, `ghostty_terminal_select_word` and `ghostty_terminal_select_line` with Ghostty's default boundaries and whitespace, `ghostty_terminal_point_from_grid_ref` for the result, and `ghostty_terminal_selection_format_alloc` with plain output, `unwrap` and `trim`. Struct offsets come from the manifest, as in ADR 041. `selectionText` clamps endpoints to the screen, so a selection whose rows have left history copies what is left.
- **SelectionManager.** Its absolute rows were already scrollback length plus active row, which is Ghostty's screen row, so the state, the drag, the auto-scroll and the renderer's range (ADR 043) are unchanged. `getSelection` calls `selectionText`. A double click calls `selectWord`, a triple click `selectLine`, at the cell under the pointer; when Ghostty finds nothing (an empty cell, a blank line), nothing is selected, as before. `getWordAtCell`, the per-row text builder with its spacer and wide-character rules, and the triple-click row scan are deleted (186 lines; the file is 722 lines).

Kept as before: drag with its half-cell threshold, double and triple click, `copyOnSelect` copying once per gesture, selections made while scrolled and in scrollback, selections kept while output arrives and cleared on typing, a font change, a new press and a click outside (the current rules), the right-click `copyPaste` path of ADR 011 (it reads `getSelection`), and the highlight drawn by `renderer.ts` from `getSelectionRange`.

## Consequences

Behaviour that now follows Ghostty:

- **Soft wraps are joined.** A selection across a soft-wrapped row copies one line: a wrapped command or URL pastes whole. Hard newlines stay.
- **Words.** Boundaries are whitespace and `` ' " │ ` | : ; , ( ) [ ] { } < > $ `` (Ghostty's default `selection-word-chars`, checked on the pinned wasm); every other character, non-ASCII letters included, is part of a word. A URL with `?`, `=`, `&` or `#` selects whole, `café` and `中文字` select whole, and a word that wraps selects across the wrap. Before, only `[A-Za-z0-9_\-./~@+]` counted.
- **Double click on whitespace** selects the run of whitespace and copies nothing (it trims to empty), as in Ghostty. Before, it selected nothing.
- **Triple click** selects the whole logical line across soft wraps, without leading or trailing whitespace. Before, it selected one row from column 0, indent included.
- **Wide characters.** Ghostty skips spacers and takes the whole character from either half, as a1671fa did. A selection that ends on the spacer at the end of a row, where a wide character did not fit and wrapped, now copies that character.
- **Work per copy.** The text is built in one wasm call instead of decoding every selected row into JS cells; a click resolves one grid reference and reads back two.

Not changed, and why:

- **Highlight state stays in JS.** The renderer draws the selection over overscan rows outside the viewport (ADR 043), in canvas rows. The binding keeps Ghostty's viewport at the bottom and reads scrollback through a second render state a page at a time, so the render state's per-row selection covers only the active screen. Reading it would add a call per row per frame for nothing the range does not already give.
- **The terminal-owned selection and tracked references are not used.** Absolute rows drift by the rows pruned once history is full (10,000 lines by default, ADR 046): a selection held while a full scrollback keeps growing moves up with the text. This is not new: the old code used the same rows. Tracked references (`ghostty_terminal_grid_ref_track`) would fix it. Installing the selection in the terminal would also hand its lifetime to Ghostty, which would have to be checked against the clearing rules above. Left as a follow-up.
- **The gesture state machine is not used.** The browser already counts clicks (`MouseEvent.detail`) with the OS settings, and the manager's DOM handling (document-level drag, auto-scroll, outside clicks, the context menu) would stay. It would add word- and line-granular drags after a double or triple click, which webtty does not have; that can be a later ADR.

Size: `selection-manager.ts` loses 186 lines of Coder code and gains 21; the binding gains about 190 lines, most of them layout and comments.

## Considered Options

- **Words, lines and text from Ghostty, state and highlight in JS (chosen).** Replaces the parts that encode terminal knowledge, keeps the renderer and the gesture code that webtty has already fixed.
- **Install the selection in the terminal and render from Ghostty's state.** Fixes the pruning drift, but needs the renderer to read selection rows from tracked references every frame, and moves the clearing rules to Ghostty.
- **Use `ghostty_selection_gesture_*` for the whole gesture.** Removes the click counting and threshold, adds granular drags, but re-feeds time and distance the browser already resolved, and most of the manager is DOM code that stays either way.
- **Keep the TS code and fix it.** Unicode word characters, soft-wrap joining and wrapped lines would each re-implement part of Ghostty's `Screen.selectWord`, `selectLine` and `selectionString`.
