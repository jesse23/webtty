# ADR 035: Client — extend the edge colours into the leftover strip

**SPEC:** [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-09-21

---

## Context

The canvas is fitted to whole cells, so a strip of less than one cell is always left at the
right and bottom ([ADR 033](033.client.padding-fit.md), [ADR 034](034.client.padding-config.md)).
It cannot be removed: filling it would need rows of a fractional pixel height, and ghostty-web
draws cell backgrounds and text at those fractional positions, which shows as seams and
blur. A single colour hides the strip only where the app's edge cells share that colour. A
multiplexer with a dark sidebar next to a light main area has two edge colours along the
bottom, so any one colour leaves a visible patch.

Terminal emulators solve this by stretching the edge cells' own background into the
padding. Ghostty calls it `window-padding-color = extend`.

## Decision

The client always extends the edge colours into the leftover strip, with no setting. It
adds two overlay strips, one under the canvas and one to its right, and keeps them painted
from the canvas' last pixel row and last pixel column, stretched across the leftover. The
strip therefore takes on the background of the edge cells in every column and row.

Only the leftover is extended. The space set by `padding` keeps the container background
colour, `theme.padding` or `theme.background`, so `theme.padding` stays a plain colour and
only matters when `padding` is above `0` (and for the bottom-right corner, where the two
strips meet).

It is not an option because there is no reason to prefer a visible seam: extending only
affects less than one cell of leftover that otherwise shows a colour that matches nothing.

## Considered Options

### Option A: Always stretch the edge pixel row and column into the leftover (chosen)
Seamless for any app at any window size, no config, the same result as Ghostty's `extend`.
Costs two small overlay canvases repainted each frame, one `drawImage` each.

### Option B: Make it a setting, off by default
Keeps the old look for anyone who wants it, but adds a key for a behaviour nobody needs to
avoid, and leaves the seam by default. Rejected. Can be added if a real case appears.

### Option C: One colour for the leftover
Hides the strip only where the edge cells share the colour. This was the earlier behaviour.

### Option D: Stretch rows to fill the height
Removes the strip, but fractional row heights give seams between backgrounds and uneven
text. Rejected.

### Option E: Reflect the canvas with `-webkit-box-reflect`
CSS only, but it mirrors the last few pixels including any text descenders, and is
Chromium-only. Rejected.

## Consequences

**Positive**
- The strip is invisible at any window size, for any app, with no setting.
- `theme.padding` stays a plain colour with one job.

**Negative**
- Two extra canvases repainted every frame while a strip is present.
- The bottom-right corner, where both strips meet, stays the container background.
- If the edge cells' last pixel row is not their background, for example a full-width
  line drawn on the very last row, that colour is stretched.
