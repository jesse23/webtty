# ADR 033: Client — fit without the scrollbar reserve, and a `theme.padding` colour

**SPEC:** [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-09-21

---

## Context

[ADR 022](022.client.canvas-fill.md) centres the canvas by measuring the gap between the
container and the canvas and distributing it as padding on `#terminal`. It also records
that ghostty-web's `FitAddon` always subtracts a fixed 15px scrollbar reserve, even
though the container has no scrollbar, and that the fix belongs upstream.

The scrollbar in ghostty-web is drawn as an overlay inside the canvas, so the reserve
buys nothing, but it does leave a visible strip: about 15px plus the sub-cell remainder,
split across both sides. Against a full-screen TUI that paints its own edge cells, such
as a multiplexer with a darker sidebar, that strip is a band in the default background
colour between the browser chrome and the app. It shows at all four edges. Only
`theme.background` was available to colour it, and that is also the terminal's default
cell colour.

## Decision

Two changes, both aimed at the visible strip:

1. **Fit from the full container.** The client no longer uses `FitAddon`. A small
   `computeGrid()` in `src/client/fit.ts` derives cols and rows from the container size
   and the renderer's cell metrics, with no scrollbar reserve. The fit also runs again after the font is remeasured (`document.fonts.ready`), since that changes the cell size. What is left over, less
   than one cell, is still distributed as padding by the existing measured-gap code, so
   the canvas stays centred.
2. **An optional `theme.padding` colour.** The `#terminal` container, whose background
   shows only in that padding, takes `theme.padding` when set and `theme.background`
   otherwise, so existing configs render as before. (Superseded in part by [ADR 035](035.client.edge-extend.md): the leftover strip is now
   extended from the edge cells, and `theme.padding` colours only the space set by `padding`.) `padding` is a webtty setting, not a
   terminal colour, so the client removes it from the theme object before handing the
   theme to ghostty-web.

## Considered Options

### Option A: Local fit without the reserve, plus `theme.padding` (chosen)
Removes almost all of the strip, and lets the rest be coloured to match the app. Costs a
small local replacement for `FitAddon` and one theme key.

### Option B: Wait for the upstream `FitAddon` option
ADR 022 already lists this contribution. It is the long-term fix, but it does not help
until released and adopted. The local fit is small and easy to delete once upstream
supports `scrollbarWidth: 0`.

### Option C: Only add the colour
Hides the strip instead of shrinking it, and the strip stays about 16px wide. Rejected as
the sole change; kept as the second half of this one.

### Option D: Colour the padding from the edge cells automatically
Needs per-frame pixel reads and still shows a seam where the edge colour varies. Rejected.

## Consequences

**Positive**
- The strip at the edges shrinks from about 16px to under one cell (typically a few px).
- The remainder can be coloured to match a full-screen app's edge colour.
- No change for existing configs, other than a slightly larger grid.

**Negative**
- The grid is up to one column wider than before (the reserve is gone), so a program that
  hard-codes widths may reflow once.
- ghostty-web's overlay scrollbar, shown only while scrolling back, can overlap the last
  column, since that strip is no longer left empty.
- Users choose one padding colour for all four edges, which is exact only if the app's
  edge cells share it.
