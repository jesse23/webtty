# ADR 061: client — Splitting the vendored ghostty-web layer, provenance kept

**SPEC:** [architecture](../specs/architecture.md), [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

`src/client/vendor/ghostty-web/` started as Coder's ghostty-web `lib/` at `1858a59` (MIT, ADR 041) and has since been rewritten around Ghostty's official libghostty-vt (ADR 042, ADR 047) and twenty-odd later ADRs. Five files hold most of it:

- `ghostty.ts` (3061): every wasm call — engine types, the export typing, the manifest reader, about 320 lines of layout tables, the loader, the scratch allocator and `OfficialTerminal` (about 1,770 lines covering render state and row decoding, the scrollback page cache, selection, search, the mouse, focus and paste encoders, the wasm callbacks and effects), and `OfficialKeyEncoder`.
- `terminal.ts` (2147): the `Terminal` facade with about 45 private fields and 9 emitters, doing options, DOM setup, focus tracking, the write pipeline, find, clear screen, the viewport, wheel routing, mouse and links, the scrollbar animation, the render loop and teardown.
- `renderer.ts` (1508): contracts, the default theme, DPR helpers, band planning, row repainting, cell painting, the cursor and its blink timer, and the scrollbar.
- `input-handler.ts` (856): the key table, key encoding, IME de-duplication, mouse reports; a seven-argument constructor.
- `selection-manager.ts` (736): selection state, gestures, auto-scroll, the context-menu textarea and a three-way clipboard fallback.

Collaborators reach each other through `any` (`(terminal as any).wasmTerm`, `.renderer`, `.getViewportY`), type-only import cycles (`buffer` ↔ `terminal`, `selection-manager` ↔ `renderer` ↔ `terminal`), and duplicated logic (the scrollbar geometry in both the renderer and the terminal's hit test; the inclusive cell-range test three times). Tests reach private members through 54 `as unknown as {…}` casts. The licence trail is `PROVENANCE.md`, whose "Local changes" log is keyed by file name.

The layer has hot paths: per-cell decode (`decodeRow`, `readStyle`, `readGrapheme`) and per-cell paint (`renderCellText`) run for every dirty cell every frame, and the binding has a memory rule: no view of wasm memory outlives an export call.

## Decision

### Facades stay at their paths, parts move into subfolders

`ghostty.ts`, `terminal.ts`, `renderer.ts`, `input-handler.ts` and `selection-manager.ts` stay where they are as facades: their public classes and re-exports, under the limits in the SPEC. Their parts move into `engine/`, `core/`, `render/`, `input/` and `selection/` (the SPEC lists every file). Keeping the facades in place means the barrel, every deep import in tests and `git blame` on the facade keep working, and the PROVENANCE log stays keyed by names that still exist. The root `LICENSE`, `LICENSE.ghostty-vt-js`, `PROVENANCE.md` and `fn-table.ts` do not move, so `scripts/build.ts` reads the same paths. `vendor/ghostty-vt/` does not move.

The webtty-original modules already in the tree (`glide.ts`, `wheel.ts`, `mouse-route.ts`, `search.ts`) stay in it: the vendored code uses them, and it must not import app code. The app reaches them, and `watchDevicePixelRatio`, through the barrel instead of deep paths.

### Shared engine state is explicit

`OfficialTerminal` becomes a facade over per-feature bindings (`render-state`, `scrollback-pages`, `selection-binding`, `search-binding`, `mouse-encoder-binding`, `paste-focus-binding`, `key-encoder-binding`, `engine-effects` for the `FnTable` callbacks, the clipboard write and `readTitle`, `grid-refs` for the grid and screen refs, `hyperlinkAt` and graphemes, and `engine-config` for `applyConfig` and the colour reads and writes) that share one `EngineContext` (`ex`, the layout, the scratch allocator, the terminal handle, the generation counter, and `dv()` / `u8()`, which build memory views per call and are never stored in a field). Each binding declares its own scratch slots, so the 40-slot table is no longer written twice. The wasm callbacks are still installed through `FnTable` and uninstalled in `free()`, and still never re-enter `vt_write`. `resolveOfficialLayout` returns typed per-feature sub-objects instead of a `ReturnType<…>` blob. What stays in the facade is the constructor and fields (budget about 150 lines: the bindings are created there and own their state), the public API as one-line delegations, the small mode and viewport calls (`getMode`, `scrollViewport`, `promptJumpRow`) and `free()`; `info()` and `allocView` move into `EngineContext`. The `*-binding` suffix names every file that wraps one libghostty-vt object, so `engine/key-encoder-binding.ts` (the wasm key encoder) is not confused with `input/key-encoding.ts` (the DOM key table lookup), nor `engine/mouse-encoder-binding.ts` with `input/mouse-report.ts`, `mouse-route.ts` and `core/mouse-controller.ts`. The vendored options store is `core/options-proxy.ts`, so the app's `app/terminal-options.ts` keeps a unique basename.

### Narrow host interfaces break the cycles

Collaborators depend on interfaces in `core/host-types.ts`, `engine/engine-types.ts` and `render/renderable.ts` (`IViewportHost`, `IBufferSource`, `SelectionHost`, `SelectionSource`), never on the facade class as a value. `buffer.ts`, `selection-manager.ts` and `addons/fit.ts` stop using `any` to reach into `Terminal`.

### Duplicates become one module

`render/scrollbar-geometry.ts` serves both the scrollbar painter and the terminal's hit test; `render/cell-range.ts` is the one range shape and inclusive test, used by the renderer and `LinkDetector`; the two link providers share one `openLinkOnModifier`; the three IME de-duplicators become one `EchoGuard` with an injected clock.

### Hot paths are kept as they are

`render-state.ts` keeps the hoisted locals, the reused `Uint32Array`, the per-row style cache and the generation-gated refresh in one unit (the one file allowed 700 lines). The painters take the target context as a parameter instead of swapping `this.ctx` for the scratch canvas, and every painter bumps the one draw counter that `visibleArea.version` (and so the edge strips) depends on. Painter methods stay monomorphic and allocate nothing per cell. The steps that touch these paths record `official-replay.test.ts` timings before and after in the commit message.

### Order inside the layer is kept

Listener targets, phases, `capture` flags and registration order in `open()` are unchanged (webtty's own capture listeners depend on them); the render loop keeps `beforeRender` → find step → render → drain replies → anchor the textarea; `writeInternal` keeps clear-at-ground → write → drain replies → focus-mode edge → effects → link cache → auto-scroll and echo render. Timer values (16 ms mouse throttle, 530 ms cursor blink, 50 ms auto-scroll, 100 ms de-duplication window, 10 ms context-menu delay) move to named constants with the same values.

### Provenance

- **Headers.** Every file holding Coder-derived code starts with `// Derived from coder/ghostty-web lib/<original>.ts (MIT, see LICENSE and PROVENANCE.md in ghostty-web/).` Every webtty-original file starts with `// webtty (ADR NNN), not from upstream.` `(webtty, ADR NNN)` tags move with their lines.
- **`PROVENANCE.md`** gains a **Moves and splits** table (original file and symbol group → new file), appended by each split commit; a **webtty-original files** list; and a **Layout** note per subfolder. The "Local changes" bullets stay, with the new file names added. The note "diff against the commit that added them" is extended: moved lines are followed with `git log --follow` on the facade and the Moves table.
- `fn-table.ts` keeps its ghostty-vt-js header and licence and is not merged into Coder-derived files.

### Lint scope and tests

The vendored tree stays excluded from Biome (one rule; moved Coder code is not reformatted) and stays under `tsc --strict`; the architecture checker applies the size and import rules to it anyway. Its tests move to `src/client/vendor/tests/`, mirroring the subfolders, with a shared `support/wasm.ts` (one wasm path, one cached compiled module), and stay Biome-linted.

### Small cleanups that come with the split

- `InputHandler` takes one options object (its own commit; the call sites in `terminal.ts` and the tests change with it).
- Dead code goes: `keypressListener`, `SelectionManager.requestRender` (a no-op called six times), the unused `rect` in `prepareContextMenu`, the empty `handleCompositionUpdate`.
- `Ghostty.load(path)` keeps its signature; loading moves to `engine/wasm-loader.ts` with its default URL corrected for the new depth (`../../ghostty-vt/…`).
- The barrel's stale header (`@cmux/ghostty-terminal`) and the usage comment in `terminal.ts` are fixed.

## Considered Options

- **Move everything into subfolders, facades included** (`terminal/terminal.ts`, `render/canvas-renderer.ts`). Cleaner tree, but breaks every deep import and blame on the most edited files at once, and the PROVENANCE log would name files that no longer exist. Rejected for the facades; adopted for their parts.
- **Move the webtty-original modules out of `vendor/`.** Makes ownership plain, but the vendored code would then import app code, inverting the layer. Rejected; the headers and PROVENANCE mark them instead.
- **Lint the whole vendored tree with Biome.** Would reformat every Coder line and bury the real diffs. Rejected.
- **Leave the vendored layer as it is** and refactor only the app. Rejected: these five files are most of the client and most of its untested code.

## Consequences

- No vendored file is over 600 lines (700 for the decode hot path, data tables exempt), and each has one job.
- Controllers with injected rAF, timers and DOM can be tested without a browser; `terminal.ts` coverage (53% of lines today) can rise to the layer's target.
- The licence boundary stays readable file by file, and the Moves table keeps the upstream diff traceable.
- The split is the riskiest part of the refactor, so it comes after the app-layer work and is done one facade at a time, each step leaving the replay, raster and terminal tests green.
