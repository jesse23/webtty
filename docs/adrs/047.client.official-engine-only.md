# ADR 047: client — Official libghostty-vt as the only engine

**SPEC:** [client](../specs/client.md), [config](../specs/config.md)
**Status:** Accepted
**Date:** 2026-10-13

---

## Context

ADR 042 added Ghostty's official libghostty-vt wasm as a second engine behind `?engine=official`, with the Coder engine (`ghostty-web`'s patched December 2025 wasm) as the default until its acceptance matrix was recorded. ADR 041 step 5 then deletes the Coder engine and the workarounds the official API makes unnecessary, "after one release with `official` as the default", and its rollback for step 3 keeps `?engine=coder` as a per-tab fallback for that release.

Since ADR 042, every client change has been built and checked on the official engine first: page reads and the scrolled view (ADR 042), scroll copy and overscan (ADR 043, 45 browser states on the official engine), smooth wheel scrolling (ADR 045) and scrollback in lines (ADR 046, official only). The Coder engine is now the one that gets less testing, and it keeps a few hundred rows of history where the official engine keeps 10,000 lines.

On 2026-10-13 the user ran the official engine by hand in Chrome, Firefox and Safari and found nothing wrong. The checks on record are in ADR 042's acceptance record.

Keeping the Coder engine costs:

- about 780 lines in `ghostty.ts` (`CoderGhostty`, `CoderKeyEncoder`, `CoderTerminal`), a 423,939-byte wasm with its sidecar, licence and test, a served route, and an engine switch;
- interface members and branches that exist only because there are two engines: `answersSizeQueries`, the stream scan for BEL and OSC 0/2, `colorsSet`, `scrollbackLimit` and the client's `scrollback / 80` derivation, and the `kitty.ts` size replies;
- parity tests that use the Coder engine as their reference.

## Decision

Make the official libghostty-vt wasm the only engine now, and delete the Coder engine, instead of first shipping a release with `official` as the default (ADR 041 step 5's rule). The per-tab `?engine=coder` fallback goes with it: a regression found later is fixed forward on the official engine, or the deletion is reverted with git. In return, every path the client runs is the one that gets tested.

**Deleted now.**

- **Engine selection.** `src/client/engine.ts` and its test. `index.ts` loads `/ghostty-vt-small.wasm` directly. `?engine=` in old URLs is ignored.
- **The Coder engine in `ghostty.ts`.** `CoderGhostty`, `CoderKeyEncoder`, `CoderTerminal`, the `EngineName` type, the engine parameter of `Ghostty.load`, and the abstract base with two subclasses. `Ghostty.load(path)` returns the official engine. Its default path, used by the vendored `init()`, points at the official wasm. The vendored `index.ts` stops exporting `CoderTerminal` and `EngineName`. The `GhosttyTerminal` and `KeyEncoder` interfaces stay: the renderer, selection, buffer, input handler and test fakes are typed against them.
- **The Coder wasm.** `ghostty-web/ghostty-vt.wasm`, its sidecar `ghostty-vt.wasm.json`, `LICENSE.ghostty` (Ghostty's licence for that wasm only) and `ghostty-web.test.ts`. `scripts/build.ts` stops copying the wasm and drops its `THIRD_PARTY_LICENSES` block; the ghostty-web entry now covers only the TypeScript bundled into `client-browser.js`. `ghostty-web/LICENSE` (Coder, MIT) stays, because the vendored TS is still Coder's code.
- **Serving `/ghostty-vt.wasm`.** `src/server/static.ts` resolves only `ghostty-vt-small.wasm`, so `GET /ghostty-vt.wasm` returns 404. The route test serves `/ghostty-vt-small.wasm` byte for byte against its sidecar, and the packed-dist test stops copying the Coder wasm. A `dist/ghostty-vt.wasm` left by an older build does no harm, because nothing serves it.
- **Coder-only types** in the vendored `types.ts`: `GhosttyWasmExports`, `GHOSTTY_CONFIG_SIZE`, `CURSOR_STRUCT_SIZE`, `COLORS_STRUCT_SIZE` and `TerminalHandle`. Upstream leftovers that were unused before this change (`SgrAttribute*`, `RGBColor`, `TerminalConfig`, `TerminalMode`) stay. They are not engine code, and removing them would only churn the vendored file.
- **Two-engine interface members.** `answersSizeQueries` goes. `setViewportOffset` becomes required on `GhosttyTerminal`. `readEffects`, `setCellPixelSize` and the pixel arguments of `resize` stay, because the official engine uses them; their "no-op on Coder" comments go. Comments that say rows are "in the Coder engine's coordinates" now say active-screen rows, with `getScrollbackLine(i)` counted from the oldest row.
- **Stream-scanned bell and title.** `writeInternal` no longer scans output for BEL and OSC 0/2, and `checkForTitleChange` goes. Bell and title always come from `readEffects` (Ghostty's `BELL` and `TITLE_CHANGED`).
- **Scrollback derived from `scrollback`.** The client stops passing `Math.ceil(config.scrollback / 80)`, and the terminal's `scrollback` option, `GhosttyTerminalConfig.scrollbackLimit` and the derived byte limit go. The binding always sets `SCROLLBACK_MAX_LINES` from `scrollbackLines` (default 10,000; NULL for 0) and `SCROLLBACK_MAX_BYTES` to 32 MiB. A `Terminal` built without config now keeps 10,000 lines instead of the wasm's 10,000-byte default. `/api/config` still serves `scrollback`, the server's replay buffer (ADR 046), and the client no longer reads it.
- **`colorsSet` and 0 as "unset".** The mask was needed because the Coder config struct encoded an unset colour as 0, which is also `#000000`. Theme colours become `number | undefined`, and undefined means unset. The 0xcccccc / 0x000000 fallback for a missing foreground or background stays, because Ghostty applies the default colours only when both are set (ADR 042). It is now described as webtty's default.
- **`kitty.ts` size replies** (ADR 041 step 5, "size reports answered by Ghostty through `OPT_SIZE`"). On the official engine they were already suppressed (`answersSizeQueries`), and Ghostty answers XTWINOPS 14/16/18/19t and mode 2048 from `OPT_SIZE` with the same device-pixel cell size. `SIZE_QUERY`, `sizeQueries`, `TerminalSize`, `sizeReply`, `ControlScan.queries` and `graphics.ts`'s `terminalSize()` go. `ControlScanner` (clear detection), `deviceCellSize` and `axisScale` (frame scaling) stay.

**Tests rewritten, not dropped.**

- `engine-parity.test.ts` (renamed `official-replay.test.ts`) used the Coder engine as the reference for the official engine's scrolled view, page cache and generation counter. Those tests now compare against a fresh official terminal that was fed the same bytes and is read at offset 0, so stale pages and lost dirty rows still fail them. The #180 stress payload test stays. The PTY captures in `fixtures/` stay as a chunking check: each capture written in 512-byte and in 1-byte writes must give the same screen.
- `renderer.test.ts` runs its engine-parameterised tests on the official wasm only, and its single Coder-wasm test moves to the official wasm.
- `official-terminal.test.ts` loads through the new `Ghostty.load(path)`. The `scrollbackLimit` cases move to `scrollbackLines`, and the test that contrasts the old byte limit goes.
- A `terminal.test.ts` case checks that a title and a bell reported by `readEffects` reach `onTitleChange` and `onBell`.

**Workaround replacements (ADR 041 step 5).**

| Item | Now or later | Why |
|---|---|---|
| Coder wasm and sidecar | Now | Above. |
| Size reports through `OPT_SIZE` | Now | Already what runs on the official engine; deleting the `kitty.ts` replies removes dead code. |
| Official key encoder | Done | `OfficialKeyEncoder` already runs on `ghostty_key_encoder_*`. The name translation from ghostty-web's `Key` enum stays (ADR 041: layouts and enums come from `ghostty_type_json`). |
| Cursor style from the render state | Follow-up | Possible with `DEFAULT_CURSOR_STYLE` / `DEFAULT_CURSOR_BLINK`, but the renderer would take shape and blink from `getCursor()` each frame. Hollow block needs mapping, and Ghostty's blink also follows mode 12, which changes behaviour for apps. The DECSCUSR scan in `terminal.ts` works and stays until an ADR 013 update with wasm tests and a vim/nvim check. |
| Official mouse encoder | Follow-up | The TS encoders carry webtty's fixes (hover Cb=35, per-cell motion, release outside) and ADR 045's wheel pacing. Replacing them changes behaviour that ADR 017 and 045 settled, and needs its own ADR and a vim/htop/tmux/less check in three browsers. |
| `terminal_paste` / paste encoding | Follow-up | Ghostty brackets every paste while mode 2004 is on and filters unsafe bytes. ADR 014 (Ctrl+V for images) and ADR 037 (bracket multi-line only) decided otherwise. A change is a product decision for its own ADR. |
| Theme colours from the render state | Follow-up | The renderer, edge strips, padding and IME composer paint from the static theme, so OSC 10/11/12 and DECSCNM change cell colours but not the canvas clear or cursor colour. Fixing that touches several components and ADR 036. |

Kitty keyboard flags (ADR 042, Consequences) remain future work as before.

**Rollback.** Git revert of the deletion commits. There is no per-tab fallback and no build-time switch.

## Consequences

- One engine: about 780 lines of `ghostty.ts`, the Coder wasm (423,939 B), its sidecar, licence and test, and `engine.ts` are gone. The repo carries only the official wasm pin.
- `/ghostty-vt.wasm` returns 404, and `?engine=coder` no longer selects anything. Every tab runs the official engine with 10,000 lines of history by default, and gets the replies ADR 042 lists (DA3, XTWINOPS 19t, mode 2048, OSC 4/10/11, DECRQM, XTVERSION).
- A regression found in a browser the user did not check cannot be avoided per tab; it is fixed forward or reverted.
- The client config type drops `scrollback`; the server and `/api/config` are unchanged, so no config migrates.
- The `kitty.ts` size replies are gone, and Ghostty is the only source of size reports.
- The cursor-style scan, the TS mouse and wheel encoders, `paste.ts` and the static theme stay. Each is now a single-engine workaround with its own follow-up (above), not a parity requirement.
- `GhosttyTerminal` and `KeyEncoder` stay interfaces with one implementation, so test fakes keep working, and a later engine change would not touch the renderer.

## Considered Options

- **Delete the Coder engine now (chosen).** Less code and one tested path, in exchange for the per-tab fallback.
- **Flip the default and keep the Coder engine for a release (ADR 041 step 5's plan).** Keeps `?engine=coder` as a fallback, but every change in that release would have to keep both engines working and their parity tests passing. The official engine was already the only one carrying new work (ADR 043–046).
- **Flip the default and delete the Coder engine, but keep the `kitty.ts` size replies and the stream scan "just in case".** Both are dead code on the official engine. Keeping them only hides what the code depends on.
- **Do every ADR 041 step 5 replacement in the same change.** Cursor style, mouse, paste and theme colours each change what apps or users see, so each needs its own decision and browser checks. Deleting the Coder engine changes none of them.
