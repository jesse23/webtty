# ADR 040: client — Pixel-smooth scrollback scrolling

**SPEC:** [client](../specs/client.md)
**Status:** Proposed
**Date:** 2026-10-12

---

## Context

ghostty-web's viewport is a whole number of lines: `render()` floors `viewportY` when it picks rows, and draws only full rows. A macOS trackpad reports fine pixel deltas with native momentum, but ghostty-web turns them into a line count and eases toward it over 100 ms, so scrolling steps a line at a time and trails the fingers.

## Decision

Keep the scroll position as fractional lines in the client (`src/client/smooth-scroll.ts`) and take over wheel events on the normal screen when the app is not tracking the mouse:

- The whole part goes to ghostty-web as `viewportY` (`scrollToLine`), which renders those rows as usual.
- The fraction becomes a CSS offset snapped to device pixels: the canvas is translated down by `fraction × cellHeight` with its bottom edge clipped, and a one-row strip above it shows the scrollback line sliding into view. The strip is drawn with ghostty-web's own `renderLine`, with the renderer's context swapped for the strip's, so it matches the canvas exactly.
- At a whole-line position the canvas has no transform and the strip is hidden; a resting terminal renders as before.
- ghostty-web's own viewport moves (output snapping to the bottom, keyboard scrolling, scrollbar drag, resize) reset the position to its line.

The alternate screen and mouse-tracking apps scroll their own view in whole lines, so no pixel offset is possible there. For mouse-tracking apps (herdr, Claude Code's fullscreen TUI, vim `mouse=a`), count pixel wheel deltas by distance instead: one SGR scroll tick per cell height scrolled, times `mouseScrollSpeed` (ADR 017). Previously every wheel event was one tick, so a trackpad's many small events and momentum scrolled far ahead of the fingers. Line and page deltas still count one tick per event.

## Consequences

- Trackpad scrolling through scrollback follows the fingers pixel by pixel, with macOS momentum, and no easing lag.
- A mouse wheel with large pixel steps jumps by those steps without ghostty-web's easing.
- In mouse-tracking apps, trackpad scrolling now moves about one line per line of finger travel. On macOS, Chromium and Safari report mouse wheels in pixels too, so a wheel notch now sends a distance-based number of ticks instead of exactly one; users who raised `mouseScrollSpeed` to compensate for slow wheels may want to lower it.
- Uses private ghostty-web renderer members (`ctx`, `renderLine`); an upgrade that changes them breaks the strip.
- While at a fractional position: the overlay scrollbar moves with the canvas by under a line, Kitty graphics placements are not offset, and the bottom edge strip (ADR 035) extends the clipped last row.
