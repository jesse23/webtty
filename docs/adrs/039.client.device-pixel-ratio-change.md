# ADR 039: client — Follow devicePixelRatio changes

**SPEC:** [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-10-12

---

## Context

ghostty-web's `CanvasRenderer` reads `window.devicePixelRatio` once in its constructor and sizes the canvas backing store (`cols × cellWidth × dpr`) from that value for the rest of the page's life. Moving the window to a monitor with a different scale (Retina ↔ external display) or changing browser zoom changes the ratio, but the renderer keeps the old one: text renders blurry or mis-scaled until the page is reloaded.

The canvas' CSS size does not change when only the ratio does, so the container `ResizeObserver` does not fire, and the window `resize` that does fire runs `fit()`, which sees the same cols and rows and does nothing (ADR 033).

A fractional ratio (browser zoom other than 100%, Windows 125%/150%) breaks the renderer outright. `render()` compares the integer `canvas.width` against the unrounded `cols × cellWidth × dpr`, so the check fails on every frame and the canvas is resized, cleared and fully repainted about 60 times a second while idle. Cell edges also fall between device pixels and leave hairline seams. This is coder/ghostty-web#198.

## Decision

Set the renderer's (private) `devicePixelRatio` to `Math.ceil(window.devicePixelRatio)` after `open()`, and again whenever `matchMedia('(resolution: <dpr>dppx)')` stops matching, then force a full render, schedule a fit, and re-arm the query for the new ratio. The forced render sees that the backing store no longer matches `cols × cellWidth × dpr` and resizes and repaints the canvas itself, the same self-correction ADR 031 relies on.

Rounding up keeps `cols × cellWidth × dpr` an integer (cell sizes are whole CSS pixels), so the per-frame resize never starts, and puts cell edges on whole pixels of the backing store, which the reporter of #198 found removes the seams. The browser scales the canvas down to the real ratio.

### Considered Options

- **Patch ghostty-web to compare against `Math.round(...)`** — stops the per-frame resize at the exact ratio, but needs a dependency patch in the build and leaves the seams.
- **Round up the ratio (chosen)** — no patch, fixes both; costs a larger backing store at fractional ratios.

**Update (ADR 041):** the logic now lives in the vendored renderer (`src/client/vendor/ghostty-web/renderer.ts`): it rounds the ratio up (`wholeDevicePixelRatio`), rounds backing-store sizes the same way in `resize()` and `render()`, and follows changes itself (`watchDevicePixelRatio`); its next frame resizes and repaints the canvas. `index.ts` only schedules a fit on a change. The private-field cast is gone.

## Consequences

- Moving between displays of different scale keeps text crisp without a reload.
- At a fractional ratio the canvas no longer resizes every frame (measured at 1.36: 60/s on `main`, 0 with this change).
- At a fractional ratio the backing store is larger than strictly needed (e.g. 2× instead of 1.36×), and text is drawn at the higher ratio and scaled down by the browser rather than drawn at native resolution.
- Depends on a private field of ghostty-web's renderer; an upgrade that renames it would silently drop the fix (the cast compiles either way). Revisit once coder/ghostty-web#198 is fixed upstream. (Resolved by ADR 041: the renderer owns the logic and the cast is gone.)
