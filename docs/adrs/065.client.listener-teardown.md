# ADR 065: client — Release every listener on dispose

**SPEC:** [architecture](../specs/architecture.md), [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

The vendored `Terminal` and `SelectionManager` add and remove their listeners by hand, as pairs of nullable fields, and some pairs are broken:

- `Terminal.dispose()` sets `isOpen = false` before calling `cleanupComponents()`, which removes the document and window listeners only `if (this.isOpen && …)`. After `dispose()`, the document `mouseup`, the window `focus` and `blur` and the document `visibilitychange` listeners stay attached and keep the terminal alive.
- The anonymous `beforeinput` listener on the container and the canvas `mousedown` and `touchend` listeners are never removed.
- `SelectionManager` adds a document `mousedown` listener that is never removed, and its canvas listeners are anonymous, so `dispose()` cannot remove them.
- Timers are cleared in two places (`dispose` and `cleanupComponents`).

webtty never disposes its terminal today (a page lives as long as its tab), so nothing user-visible is affected. But the refactor (ADR 060, ADR 061) makes teardown a contract that every module keeps and tests, and these leaks would make the vendored layer the exception.

## Decision

`Terminal`, its controllers, `InputHandler` and `SelectionManager` register every listener, timer, interval and animation frame in a `DisposableStore` (`lifecycle/disposable-store.ts`), and `dispose()` disposes the store. The targets, event types, `capture` flags and registration order stay as they are; only removal changes. A spy test checks that after `dispose()` every listener added to the container, the canvas, the textarea, the document and the window has been removed with the same options, and that a second `dispose()` does nothing.

The `InputHandler`'s `compositionupdate` listener, whose handler does nothing, is removed in the same commit; it is a registered listener, so removing it is a change of the listener set and belongs here, not in a move.

This is the refactor's one deliberate behaviour change, so it is its own commit (`fix(client): …`), separate from the moves. Until that commit the split steps keep today's removal behaviour exactly: a `DisposableStore` introduced by a split holds only the listeners that are removed today, and the leaking ones stay registered the old way with a comment pointing here. The listener snapshot test (ADR 064) proves it: it is unchanged by every split step and changes only in this commit.

## Consequences

- A disposed terminal leaves no listener behind, so a future multi-terminal page or a test can create and dispose terminals freely.
- Teardown is uniform across the app and vendored layers and tested the same way.
