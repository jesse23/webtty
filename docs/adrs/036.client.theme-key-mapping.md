# ADR 036: Client — map webtty theme keys to the terminal's names

**SPEC:** [client](../specs/client.md), [config](../specs/config.md)
**Status:** Accepted
**Date:** 2026-09-21

---

## Context

The config's `theme` uses Windows Terminal names: `purple`, `brightPurple` and `selection`.
The client passed the whole object straight to ghostty-web, which reads `magenta`,
`brightMagenta`, `selectionBackground` and `selectionForeground`. The three webtty names
were silently ignored. Magenta text stayed at ghostty-web's default `#bc3fbc` and the
selection stayed a light gray `#d4d4d4` with dark text, whatever the config said. The same
herdr session therefore showed different purples and a different selection in webtty than in
Ghostty, which reads the palette as written.

## Decision

The client translates the config theme once, in one function, before handing it to the
terminal: `purple` becomes `magenta`, `brightPurple` becomes `brightMagenta`, `selection`
becomes `selectionBackground`. All other colour keys pass through unchanged, and `padding`
is left out because it colours the page, not the terminal.

A new optional key `selectionForeground` sets the text colour inside the selection. When it
is not set but `selection` is, it defaults to `background`, so the text stays readable
against a custom highlight; ghostty-web's own dark default would otherwise be used against
the new highlight. When neither is set, ghostty-web's defaults are untouched.

The config keeps its existing names. Renaming them would break every existing config file.

## Considered Options

### Option A: Translate the names in the client (chosen)
One small function, covered by tests, no change for existing config files. Costs one more
key, `selectionForeground`.

### Option B: Rename the config keys to ghostty-web's
Matches the terminal exactly, but breaks existing configs and drops the Windows Terminal
names that the defaults and documentation are based on. Rejected.

### Option C: Accept both spellings
Friendlier, but two names for one colour and a rule for which wins. Rejected until a real
case appears.

## Consequences

**Positive**
- `purple`, `brightPurple` and `selection` now take effect, so the palette matches other
  terminals that read the same values.
- Contributors have one place that owns the name mapping.

**Negative**
- Configs that set `purple` or `selection` and had grown used to the ignored default will
  see the colour they wrote appear.
- The selection text colour now defaults to `background` rather than ghostty-web's default
  whenever `selection` is set.
