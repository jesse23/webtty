# ADR 058: client — OSC 133 prompt marks for zsh and bash

**SPEC:** [client](../specs/client.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

Three features read OSC 133 prompt marks: Cmd+K at a prompt (ADR 054), the prompt jumps and Ctrl/Cmd+triple-click output selection (ADR 057). fish 4 sends the marks itself; zsh and bash send none, so their users get none of the three. ADR 057 pointed them at Ghostty's integration scripts, sourced by hand, and left injection as a follow-up.

Ghostty's zsh and bash scripts are GPLv3 (they started as kitty's) and do much more than the marks (cursor shape, title, `sudo` and `ssh` wrappers), gated by `GHOSTTY_SHELL_FEATURES`. A user without Ghostty installed has to fetch them from Ghostty's repository. The marks themselves take a few lines of shell: `133;A` before the prompt, `133;B` at its end, `133;C` before a command runs and `133;D;<status>` when it is done.

## Decision

webtty documents its own snippets, MIT like the rest of webtty, for users to paste at the end of `~/.zshrc` or `~/.bashrc`. It still injects nothing.

**zsh**: a `precmd` hook sends `133;D;<status>` if a command ran since the last prompt, then `133;A`, and appends `133;B` to `PS1` if it is not there yet; a `preexec` hook sends `133;C`. Being last in `.zshrc` puts the hooks after a prompt theme's, so `PS1` is final when `B` is added, and the theme's own `$?` is untouched.

**bash**: a function first in `PROMPT_COMMAND` sends `133;D;<status>` after the first prompt, then `133;A`, appends `133;B` to `PS1` once, and returns the status it was given so later `PROMPT_COMMAND` entries see the same `$?`. `PS0` (bash 4.4 and later) sends `133;C`.

The snippets are in the client spec (Shell Prompts), next to the keys they enable. Ghostty's scripts stay listed as the alternative.

### Limits

- **bash 3.2** (macOS `/bin/bash`) has no `PS0`, so no `133;C`: prompt jumps and Cmd+K work, output selection does not.
- **bash** cannot tell an empty Enter from a command in `PROMPT_COMMAND` alone, so an empty line still gets a `133;D` (with the previous status). Nothing in webtty shows the status, and Ghostty's output selection is not affected.
- A theme that rewrites `PS1` from a later `PROMPT_COMMAND` entry (bash) drops the `B` mark; the jumps and output selection need only `A`, `C` and `D`.

### Verified

Through a PTY (40×12, `TERM=xterm-256color`) with the snippets as the only rc file: zsh 5.9 and bash 5.3 sent `A B C <output> D;0 A B …`, and zsh sent no `D` for an empty Enter; bash 3.2 sent everything but `C`. Written into libghostty-vt (the pinned wasm), both captures gave `cursorAtPrompt()` true at the last prompt, a prompt jump that moved, and `selectOutput` on a command's first output row returned exactly its output (`a.txt\nb.txt`).

## Consequences

- zsh and bash users get Cmd+K at a prompt, the prompt jumps and output selection with one paste, without Ghostty installed and without GPL code.
- webtty keeps two small snippets working; their bytes are the standard OSC 133 sequences fish 4 sends, so the terminal side is the same path ADR 057 tested with fish.
- Nothing changes for users who do not paste them; the injection follow-up of ADR 057 stays open.

## Considered Options

- **Inject the marks automatically** (ADR 057's follow-up: `shellIntegration`, `ZDOTDIR` and `--rcfile` tricks). Changes how every user's shell starts, for three features; left until someone asks.
- **Keep pointing at Ghostty's scripts only.** Needs a Ghostty install or a GPLv3 download, and brings features webtty does not use.
- **Ship the snippets as files in the npm package** (`source "$(webtty shell-integration zsh)"`). A CLI command and a file layout to keep for a dozen lines users can paste.
