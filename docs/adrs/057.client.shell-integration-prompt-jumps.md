# ADR 057: client — Jump to shell prompts and select command output with OSC 133

**SPEC:** [client](../specs/client.md), [key-bindings](../specs/key-bindings.md)
**Status:** Accepted
**Date:** 2026-10-14

---

## Context

Shells mark their prompts with OSC 133 (FinalTerm's semantic prompts): `133;A` where the prompt starts, `133;B` where the command line starts, `133;C` where the command's output starts and `133;D;<status>` where it ends. webtty passes them to libghostty-vt, which already uses them for one thing: Cmd+K at a prompt (ADR 054, `cursorAtPrompt`). Nothing else reads them.

Ghostty uses them for (`src/config/Config.zig`, `Keybinds.init`, `src/Surface.zig`, at the pinned commit `05dcf887`):

- **`jump_to_prompt:<n>`**: "Jump the viewport forward or back by the given number of prompts. Requires shell integration." Bound by default to `ctrl+shift+arrow_up` / `ctrl+shift+arrow_down` (-1 / 1) outside macOS, and on macOS to both `super+shift+arrow_up` / `super+shift+arrow_down` and `super+arrow_up` / `super+arrow_down` ("matches Terminal.app"). None is `performable:`: the key is consumed even when there is no prompt to go to.
- **Selecting a command's output**: a triple click with Ctrl or Cmd held selects the output of the command under the pointer instead of the line (`Surface.zig`, the left-click handler's gesture behaviours: `if (mods.ctrlOrSuper()) .output else .line`; `SelectionGesture.zig` calls `Screen.selectOutput`, which yields nothing outside output). There is no default key that selects or copies the last command's output.
- **Prompt clicks** (`click_events=1`, `cl=`): a click on the command line moves the cursor there. Not taken up here.

The pinned wasm exports both as C API:

- `ghostty_terminal_scroll_viewport` with `GHOSTTY_SCROLL_VIEWPORT_DELTA_PROMPT`: "Scroll by a number of prompts relative to the viewport top. Negative values move backward and positive values move forward. Requires semantic prompt markers from the shell. Zero or no matching prompt is a no-op. If fewer prompts remain than requested, move to the last matching prompt, clamped to the active area." The new position can be read back with `GHOSTTY_TERMINAL_DATA_SCROLLBAR` (`offset`, in the row space of `GHOSTTY_SCROLL_VIEWPORT_ROW`).
- `ghostty_terminal_select_output(terminal, ref, out_selection)`: the output of the command at a grid reference, `GHOSTTY_NO_VALUE` outside output.

webtty's viewport is its own (`viewportY`, rows up from the bottom, ADR 042); the binding keeps Ghostty's at the bottom and moves it only to read a page of scrollback (`readPage`), putting it back after.

**Who sends the marks.** webtty spawns the configured shell (`shell`, default `$SHELL`) with no arguments and no integration. Checked through a PTY on this machine, answering the shell's device-attributes query as a terminal does:

| Shell | OSC 133 without any setup |
|---|---|
| fish 4.9.3 | yes: `133;A;click_events=1`, `133;B`, `133;C;cmdline_url=…`, `133;D;<status>` (fish 4.0 and later emit them themselves) |
| zsh 5.9 | no |
| bash 5.3, bash 3.2 (macOS `/bin/bash`) | no |
| zsh or bash with starship 1.26 | no |
| zsh, bash 5.3 and bash 3.2 sourcing Ghostty's integration script by hand | yes |

Ghostty injects its integration automatically (`shell-integration = detect`, the default, `src/termio/shell_integration.zig`): fish and elvish by prepending a directory to `XDG_DATA_DIRS` (fish loads its `vendor_conf.d`), zsh by pointing `ZDOTDIR` at a directory whose `.zshenv` restores the user's `ZDOTDIR` and sources the user's `.zshenv`, bash by starting `bash --posix` with `ENV` set to its script, which then loads the user's startup files itself (not for macOS's `/bin/bash` 3.2). The zsh and bash scripts carry kitty's GPLv3 (they started as copies of kitty's); webtty is MIT and ships as one npm package. Beyond the marks, the scripts do Ghostty things gated by `GHOSTTY_SHELL_FEATURES`: the cursor shape, the title, a `sudo` wrapper for Ghostty's terminfo, `ssh` wrappers that call the `ghostty` binary, and `GHOSTTY_BIN_DIR` on `PATH`. With `GHOSTTY_SHELL_FEATURES` unset they emit the marks and nothing else.

## Decision

### Jump to a prompt (terminal side)

Ghostty's `jump_to_prompt`, with Ghostty's default keys for the browser's platform:

| Platform | Key | Action |
|---|---|---|
| macOS | Cmd+↑, Cmd+Shift+↑ | to the previous prompt |
| macOS | Cmd+↓, Cmd+Shift+↓ | to the next prompt |
| others | Ctrl+Shift+↑ / Ctrl+Shift+↓ | to the previous / next prompt |

- **The move is Ghostty's.** The binding's `promptJumpRow(top, delta)` puts Ghostty's viewport on webtty's top row (`ROW`), moves it with `DELTA_PROMPT`, reads where it landed from `SCROLLBAR`, and puts it back at the bottom, as `readPage` does. `Terminal.jumpToPrompt(delta)` scrolls webtty's view there with `scrollToLine`, as find does (ADR 055): the prompt row becomes the top row, the bottom is the furthest down, and SmoothScroll follows the jump. Up from the bottom goes to the nearest prompt above the screen's top row, as in Ghostty.
- **Always consumed**, as Ghostty's bindings are not `performable:`: without marks, on the alternate screen or past the last prompt the key does nothing, and it does not reach the app. The keys go through `shortcutFor` and the listener of ADR 054, so a `keyboardBindings` entry for the combo wins and `"chars": ""` turns one off.
- Output still pulls a scrolled view to the bottom (unchanged webtty behaviour), so a jump during streaming output holds only until the next output.

### Select a command's output

A triple click with Ctrl or Cmd held selects the output of the command under the pointer (`ghostty_terminal_select_output`), as in Ghostty; outside output, or without marks, it selects nothing. Like the other multi-clicks it is copied with `copyOnSelect`, and it stays the app's while the app tracks the mouse (Shift bypasses, ADR 051). There is no key for it, as in Ghostty.

### Shell side: no injection yet

webtty does not inject shell integration in this change:

- fish 4, the shell this was asked for, already sends the marks with no setup.
- The zsh and bash scripts worth vendoring are GPLv3. Shipping them in the MIT package is a licensing decision for the maintainers, not one to make in passing; writing our own is a separate piece of work.
- Injection has to be done well or not at all: the scripts must ship in `dist` and be found at run time (the CLI, the npm package and a dev checkout lay files out differently), `ZDOTDIR`, `ENV` and `XDG_DATA_DIRS` must be restored before the user's files run, bash needs `--posix` and a fallback for 3.2, and the Ghostty-only features (`sudo`, `ssh-*`, `path`) must stay off, including when the webtty server itself was started from inside Ghostty and inherited `GHOSTTY_*` variables.

Instead the specs say how to get the marks: nothing to do for fish 4; for zsh and bash, source Ghostty's integration script at the top of `.zshrc` / `.bashrc` (from a Ghostty install, or a copy of `src/shell-integration` from Ghostty's repository). With `GHOSTTY_SHELL_FEATURES` unset it only emits the marks.

**Follow-up**: a `shellIntegration` config key (`"detect"` | `"none"`, default `"detect"` as Ghostty's `shell-integration`), injecting marks-only scripts for zsh and bash (and fish 3) by Ghostty's methods, after a decision on vendoring GPLv3 files or writing MIT ones; tested with fish, zsh and bash spawned through the server.

### Replay

Neither feature has side effects: nothing is sent to the PTY, the clipboard (except through a user's own triple click) or the title. The replay on connect brings its marks with it, so the prompts before a reload can be jumped to after it.

## Consequences

- With fish 4, or zsh and bash set up as above, Cmd+↑ / Cmd+↓ (macOS) and Ctrl+Shift+↑ / Ctrl+Shift+↓ (elsewhere) step through the commands in the scrollback, and Ctrl/Cmd+triple-click selects one command's output.
- These keys no longer reach programs: Ctrl+Shift+↑ / ↓ in an editor that uses them for selection, or Cmd+↑ / ↓ in a program that reads Super, now scroll instead, as in Ghostty. A `keyboardBindings` entry gives a combo back.
- zsh and bash users get nothing until they source an integration script; webtty does not detect or warn.
- Moving Ghostty's viewport and back may report a full redraw for the next frame, as reading a page of scrollback already can.

## Considered Options

- **Find the prompts in JS** by reading each row's `GHOSTTY_ROW_DATA_SEMANTIC_PROMPT` through grid references. A walk over up to 10,000 rows per key, and Ghostty's rules (continuation rows, clamping to the active area) re-implemented; `DELTA_PROMPT` is Ghostty's own.
- **`performable` jumps** that let the key through when nothing moves. Not Ghostty's, and it would make the key's effect depend on scrollback contents the user cannot see.
- **A key to copy the last command's output.** Ghostty has none; the triple click covers selecting it.
- **Inject shell integration now.** See above; recorded as the follow-up.
- **Our own minimal zsh/bash snippets in the docs.** More for users to paste and for us to keep working across prompt themes; Ghostty's scripts already do it and work when sourced by hand (checked with zsh 5.9, bash 5.3 and 3.2).
